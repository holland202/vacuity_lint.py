======================================================================
ANTI-VACUITY SELFTEST
======================================================================

This tool exists to find suites that cannot fail. If it could only
return one verdict it would be that defect. Each fixture forces a
different answer on a case where the answer is known, and each
checks the source file is left byte-identical.

I1/I2 are a matched pair: the same fixture must read SURVIVED with
mutants traced and SURVIVED_OUT with mutants untraced. A control
that passes whatever the code does is a log line, so it is run in
both directions and the defect has to reappear on demand.

Fixture F is the coverage control: the suite exercises one
comparison and never calls the other. An instrument that cannot
tell them apart reports 50%% when the honest answer is 100%% of
what was actually measured, plus one site it never got to see.

Fixture L1 suite that refuses a second run (RE-RUNNABILITY SABOTAGE: must fail closed, not score every mutant KILLED)
  ABORT -- the suite is NOT RE-RUNNABLE. Two consecutive unmutated runs returned different exit codes (0 then 1) with no mutation between them. Mutation testing runs this suite once per mutant, so every mutant after the first would inherit that second exit code and be scored KILLED for a reason that is not the mutation. That inflates the score instead of deflating it. Refusing to measure. Make the suite idempotent, or give the audit a reset step that restores the tree between runs.

every mutant after the first would be a false KILLED;
writes a machine-readable record when it aborts;
derives its declared version from its own bytes; and leaves
the source byte-identical.
